# AGENTS.md: Ownlight engineering rules

Guidance for AI coding agents and human contributors working in this repository. If you are an agent inside the MAS workspace, the workspace constitution (`../../AGENTS.md`) applies as well. These rules add to it and never relax it.

## Product in one paragraph

A self-hosted, open-source (AGPL-3.0-or-later) CRM for photographers and videographers. One instance serves one studio. It manages leads, clients, projects or shoots through a pipeline, the calendar and bookings, packages, quotes and proposals, contracts with e-signature, questionnaires, email automations, a client portal, and gallery and video delivery. The software handles personal data of the studio's clients, so **privacy and security are product features, not chores.** See `docs/product/vision.md` and `docs/product/mvp-scope.md`.

## Stack (ADR-0002)

Next.js (App Router, React Server Components, TypeScript strict) · PostgreSQL + Drizzle ORM · Better-Auth · Tailwind CSS + shadcn/ui · next-intl (en, de) · zod · pino · Vitest + Playwright (+ axe) · pnpm · Docker Compose for self-hosting.

## Layout

```text
src/app/[locale]/...     routes (UI); thin, with no business logic
src/app/api/...          route handlers (webhooks, health, file streaming)
src/server/<domain>/     domain logic: actions.ts (server actions), service.ts, repo.ts, schema.ts (zod), policy.ts (authz)
src/server/db/           Drizzle client, schema, migrations helpers
src/components/          UI components (ui/ = shadcn primitives)
src/lib/                 isomorphic utilities (no secrets, no DB)
src/i18n/ + messages/    next-intl config and catalogues (en.json, de.json)
tests/e2e/               Playwright specs
docs/                    product, architecture (ADRs), security, privacy, operations
```

## Mandatory patterns

1. **Server actions and route handlers are public HTTP endpoints.** Every one of them must, in this order: authenticate (`requireOwner()` or a portal-scoped equivalent), authorise against the specific object (`policy.ts`), parse input with a zod schema, call the service, and return minimal data. Files under `src/server/**/actions.ts` start with `'use server'` and import `server-only` helpers.
2. **Data access is scoped.** Repository functions take the authorisation context and filter by it, and never accept bare IDs from the client without an ownership check. IDOR tests are mandatory for every new resource (owner vs. portal client vs. anonymous).
3. **Validation:** zod schemas live next to the domain (`schema.ts`), types are inferred from them, and object schemas use `.strict()`. Free-text fields have length caps.
4. **Output:** select explicit columns, never full rows, for client-facing responses. Authenticated pages send `Cache-Control: no-store`.
5. **i18n:** no literal UI strings in components. Keys are namespaced by feature (`clients.list.empty`). Every key exists in en and de. Format dates, money and numbers with the shared `Intl` helpers; store money as integer minor units plus currency.
6. **Time:** store UTC (`timestamptz`); render in the studio time zone, and show client-facing times in the time zone of the event location when relevant.
7. **Errors:** throw typed domain errors and map them to localised, generic user messages. Log with the structured logger (IDs only; PII is redacted). Never `console.*`.
8. **Files (galleries, video, PDFs):** use only the storage abstraction: private buckets, random keys, signed short-lived URLs, server-side re-encoding, EXIF/GPS stripping on delivery derivatives, and magic-byte type checks.
9. **External I/O** (SMTP, CalDAV, Google Calendar, webhooks) goes through dedicated clients with timeouts, retries with backoff, SSRF guards for user-supplied URLs, and encrypted credentials at rest. External features are **off by default** and listed in `docs/privacy/sub-processors.md`.
10. **Migrations** are generated by drizzle-kit, committed, reviewed, and reversible in practice (document the rollback steps for destructive changes). The app role has no DDL rights.
11. **Personal data lifecycle:** each new PII field gets an entry in `docs/privacy/data-inventory.md` (purpose, lawful basis, retention) and is covered by the export and erasure services, with a retention policy registered in the retention framework.
12. **Accessibility:** WCAG 2.2 AA. Use semantic HTML first, shadcn/Radix primitives for complex widgets, visible focus, and labels for every input.

## Testing

- TDD; test names contain the AC ID (`AC-3: …`). Coverage of 85 % or more on all metrics is enforced, but meaningful assertions matter more than the number.
- Unit tests for pure logic. Integration tests against the real Postgres from `compose.dev.yml` (no DB mocks for repository code). E2E tests for user-visible flows in **both** locales, with an axe check on every new page.
- Synthetic data only: fixed-seed faker, `example.com`/`example.org` domains, and generated or CC0 non-personal images.
