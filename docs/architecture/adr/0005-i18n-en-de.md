# ADR-0005: Internationalisation, English and German from day one

- Status: Accepted (maintainer decision, 2026-10-09)
- Date: 2026-10-09

## Context
Target users include German-speaking and English-speaking studios, and their clients may prefer a different language from the studio.

## Decision
- The UI is available in `en` and `de` via next-intl with locale-prefixed routes. ICU message format is used for plurals and selects.
- The studio has a default locale; each client has a preferred language used for the portal, emails and documents (contracts, proposals, questionnaires).
- Templates (email, contract, questionnaire) are stored **per language**.
- Formatting uses `Intl` with the active locale; money is stored as minor units plus ISO 4217 currency; times are stored in UTC and rendered in an explicit time zone.
- The gate enforces catalogue completeness (`check:i18n`) and a no-literal-strings lint rule.

## Consequences
Every UI task includes en and de strings and E2E checks in both locales. Adding a language means adding a catalogue plus template translations, with no code changes.

## Security & Privacy impact
The language preference is personal data with minimal sensitivity; it's stored with the client record and included in the export.
